# 医院首层平面设计 · Windows Rhino 9

插件是 Rhino 原生停靠的聊天面板。任务解析、GCN 布局、平面质检和方案评估以对话卡片显示。面板可以在 Rhino 视口预览方案，也能把通过质检的几何写入独立图层。外部 API 用于清单拟定、对话改动识别和可选布局建议。

## 安装与打开

点击「添加任务书」后，在弹窗上方拖入一个 DOCX、PDF 或 TXT 文件，或点击同一区域浏览文件。选取建筑外边界期间，设计插件面板四周会显示缓慢明暗变化的淡绿色细边框。选定闭合折线、按 Esc 或单击面板或视口空白处后，边框随即消失。

首页提供「添加任务书」「选择建筑外边界」「做一个简单平面设计」。可以先导入任务书，发送“读取任务书，拟定房间清单”，核对草稿后再选边界。空白项目的简单设计使用内置 L 形示例。已有边界时，简单设计沿用当前项目和清单。展开生成消息的用时记录，可以核对允许连接的 GCN 评分、实际门洞及患者和医护路线。

首页使用 Rhino 随附的 [Eto.Forms](https://github.com/picoe/Eto)。工具时间线使用 [Ant Design X](https://github.com/ant-design/x) 的 ThoughtChain，各阶段的交付数据使用 [Ant Design](https://github.com/ant-design/ant-design) 的 Descriptions。[LangGraph](https://github.com/langchain-ai/langgraph) 传送阶段事件，[Shapely](https://github.com/shapely/shapely) 检查几何，[NetworkX](https://github.com/networkx/networkx) 计算实际通行路径。

- 气泡聊天版位于 `bin/Chat-0.3.40/OutpatientRhino.rhp`。以下脚本在独立 Rhino 会话中打开新版，不关闭现有文档。也可在重新启动 Rhino 后通过 `PlugInManager` 加载该文件，再运行 `OutpatientPlanner`。
- 插件依赖项目现有的 Python 环境和模型权重；保持编译产物位于本仓库，或从面板的「＋」菜单选择「设置项目目录」。不需要把 API 密钥录到 Rhino。

```powershell
& 's-门诊平面生成系统/rhino/Open-Rhino.ps1'
```

如果需要从源码重新编译，先保存并关闭加载了插件的 Rhino，避免 Windows 锁定 `.rhp`：

```powershell
& 's-门诊平面生成系统/rhino/Build.ps1'
```

普通问答和方案修改回复使用 Streamdown，按收到的片段排版 Markdown，每个新增字符淡入 200 毫秒。系统开启减少动画时直接显示文字。工具执行记录使用 Ant Design X Think 和 ThoughtChain。首次构建需要 Node.js、npm 和包仓库连接。运行插件时由 Rhino 自带的 WebView2 加载本地资源。

构建使用 .NET 10 SDK 及本机 Rhino 9 的 RhinoCommon 和 Eto。Python 依赖见 [后端说明](../backend/README.md)。密钥、API 地址及可选模型名仍读取仓库根目录的本地 `.env` 或环境变量。

浮动时点击 Rhino 标题栏齿轮左侧的小图钉，停靠时点击面板右上角的小图钉，直接切换当前窗口的置顶状态。面板浮动时只置顶原浮动容器；面板停靠在 Rhino 内时会连同主窗口一起置顶。深灰实心表示已置顶，再点一次取消。切换到其他应用时，面板会维持自身浮动容器的可见性，输入焦点仍在当前使用的应用。

## 开发时实时预览

进入 Rhino 建模窗口后，点击「医院首层平面设计」工具栏的蓝色平面图标打开对话。在面板中生成一次本地预览，保持该文档打开。面板会检测项目 `backend/` 目录下直接存放的 `.py` 文件。保存后约一到两秒开始刷新，连续保存会合并；任务运行中会等它结束。预览刷新耗时取决于布局计算。

每次请求都会启动 Python 读取当前后端。只有已确认清单的本地预览会自动重算；使用外部 API 的生成仍由用户发起。已写入 Rhino 的对象保留原样。修改 C# 界面或工具栏定义后需重新构建并在新 Rhino 会话加载。

## 从边界到平面

1. 从输入框的「＋」菜单选择「选择边界」，在视口选择**一整条**闭合平面折线；默认入口在最长边，可在「＋」菜单的「方案选项」中切换。用户消息在右，回复消息在左。点击右下角箭头或按 `Enter` 发送，`Shift+Enter` 换行。
2. 任务书可选。在「＋」菜单点「附加任务书」可粘贴文字，或导入 `.docx`、文本型 `.pdf`、`.txt`；导入只在本地提取。发送「按这个边界，先拟一版门诊空间清单」。没有任务书时按边界拟定；若不联网，可从「＋」菜单选择「手工录入清单」。
3. 核对聊天中的清单，点「确认并生成」或确认后发送「生成平面」。现有要求保持不变时可直接再生成；也支持例如「诊室加一间，其他要求不变」的单项改动，需再确认草稿。修改多个不同内容或改连接约束，请打开清单编辑。
4. 四阶段进度和结果显示在对话里。预览不会创建模型对象；点结果卡「写入 Rhino」才创建，可一次撤销。「导出报告」保存独立 JSON。方案是概念图，不是墙体施工构件。

可从「＋」菜单点「试用示例」启动不联网的 L 形合成案例。普通消息通过 API 易交给 DeepSeek，可衔接最近六轮聊天。普通聊天只发送聊天文字。任务书、边界摘要和清单的发送另行确认。需求分析默认使用 deepseek-v4-flash，可通过 APIYI_DEEPSEEK_MODEL 指定网关提供的其他 DeepSeek 型号。对话状态保留在当前面板会话中，不跨 Rhino 重启保存。缺少视线目标或流线端点时相应指标标为未评估；两个搜索尝试都未通过时，不写入方案。首版仅验证 Windows Rhino 9，支持一个直线围合单区，不宣称建筑规范合规。
