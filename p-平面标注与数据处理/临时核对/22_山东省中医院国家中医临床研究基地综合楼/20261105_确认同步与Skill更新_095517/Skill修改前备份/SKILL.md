# 门诊平面结构化标注

逐张把门诊概念平面整理为可校订的空间与关系数据。先读原图和已有成果，沿用当前项目的稳定编号及已确认名称，按统一类别和以下文件规范交付；每张图独立判断，不套用其他医院的坐标或房间数量。

## 交付与精度

每张图最终只保留四个文件：具名原图（现有 `编号_项目名称_原图.ext` 沿用）、`标注.svg`、`annotation.json`、`标注说明.md`。SVG、JSON、MD 使用上述固定名称。处理经授权迁移的旧样本时，将 `标注预览.svg`、`spatial_data.json` 等分别统一为 `标注.svg`、`annotation.json`，更新当前材料中的有效链接；历史备份保留原样。仅处理当前用户指定医院，不因统一规范而批量改动其他医院。同院多张图分子目录。截图、PNG 检查图和脚本临时产物放临时目录，默认不输出网页、额外审核 JSON 或重复压缩包。清理用户已有文件须在其授权范围内。

## 名称、类别与格式统一

- JSON 的 `name` 保存原图可读或用户已确认的具体名称，`type` 使用 [space-types.json](references/space-types.json) 中的共享英文代码；标准中文类别只从同一类别表读取。财务、主任办等具体名称可共同使用 `office`，不能用医院各自的叫法生成不同类别编码，也不能从缩写补出未经确认的用途。
- SVG 可见标签统一为“稳定 S 编号＋具体名称＋〔标准功能类别〕”，与 JSON 的 `id`、`name`、`type` 对应。具体名称承载案例信息，标准类别用于跨医院比较与编码；不要为了外观一致而抹去已确认的名称。未知名称仍按未确认规则显示，不把分类推测写成具体名称。
- JSON 固定顶层 `image`、`spaces`、`relations`，UTF-8、两个空格缩进，字段遵循 [schema.md](references/schema.md)。已定位开口存于对应 `access.openings`；不添加重复的房名、类别中文、门表或过程字段。
- 后续对其他医院的补充须在用户指定的新对话中读取本 Skill，并逐张核对各自原图；固定文件名和字段结构不表示门洞及连通性已完成。

概念精度记录空间功能、范围、相对规模与可达性。**原图清晰可辨的门洞和无门开口要记录近似位置，SVG 用红点显示，并与 JSON 的人员可达关系一一对应；不能因删除施工细节而一并删除这些定位信息。**半墙服务区经图面或用户确认可达、但未画出小门时，只记录概念连接，不要求或编造门位。门宽、门扇形式、半墙缺口形状或交通核内部精确路线不纳入数据。交通核可按整体节点保存。服务窗口、共墙与人员可达分别记录。按图明确范围，不把急诊、住院支持和普通门诊无说明混同。

## 连通复核：先自主判断，再问关键疑点

默认服务于概念级空间布局研究，优先确定主要功能空间、走廊／大厅、交通核和建筑入口之间的可达关系。沿用已有空间层级、稳定 S 编号与用户确认；局部复核不继续细分功能区内部的小房间，也不要求穷尽每个小间的开门和内部连接。

提交核对材料前，先回看本图布局，将疑点分为以下三类：

- **可以自行判断：**图面连续、可见开口，或结合出入口朝向、相邻通道及完整通行组织能形成有依据的概念连接时，由助手完成判断。需要合理推断时，在 MD 简述空间对及依据，写明“布局推断”，不写成用户已确认。不能只凭共墙、服务窗口或“通常医院都会这样”建立 `access`。
- **本轮无需细究：**小设备间、管井／检修空间、辅助小间内部路线、柜台边界细碎分片等，若不影响主要功能区的通行组织，保留现有空间信息，不逐项追问精确门位或穷尽连接。证据不足的关系留空，MD 汇总为“本轮不细究的内部细节”；这不表示不相通，也不要求用户逐项确认。
- **确实需要用户判断：**助手复核后仍存在会改变主要可达关系的不同解释，例如功能区唯一出入口、主要检查室连接哪条通道、交通核对外连接哪个片区。只保留这些关键疑点，合并同片区重复问题，提出最少必要问题；不为凑固定数量而增减。

概念关系与门位定位分别处理：能判断可达但不能定位门时，可保存无 `openings` 的 `access`；清晰可见的已有门洞仍记录红点。合理推断不产生虚构门位，也不扩展为交通核或功能块内部所有小房间互通。对布局推断的说明放在 MD，不给核心 JSON 增加问答或推断过程字段。

复核旧清单时，保留原核对号和 S 编号映射，移出的细节项简述处理结果并留存已有答案；剩余问题不重新编号，也不把“无需细究”写成“用户已确认”。所有目标层级的关键疑点解决、名称同步且正式校验和目检通过后，可按该概念精度完成；无需等待非目标内部细节逐一确认。是否足够训练仍由后续模型实验判断。

## 门洞红点与连通关系同步

- 按本轮目标层级检查空间与走廊、相邻空间之间的实际开口，既有清晰门洞继续保留，不因细节项退出提问而删除。清晰门洞记为 `door`，清晰无门开口记为 `open_passage`，近似中心点采用原图像素坐标；不能从空间质心或共墙中点自动生成门位。
- 在对应 `access` 关系的 `openings` 中保存 `id`、`kind`、`position_px`，具体结构见 [schema.md](references/schema.md)。一个空间对的可达关系只保留一条，不同门在同一关系下分别记录，开口 P 编号全图唯一且续作保持稳定。
- SVG 在对应位置绘制实心红点，显示 P 编号；点的标题及属性记录关系编号和两端 S 编号。每个红点必须能回查 JSON 中的开口与空间对，每个已定位开口必须实际画出；名称标签不能遮住红点。
- 半墙未画小门、未见实体分隔的区域连续及有布局依据的概念连接只保存 `access`，可省略 `openings`；无定位红点不等于不相通。不要为满足点数编造位置，也不能因为某处位置不确定而删除其他可辨认门洞。
- 服务窗口仅记 `service`、共墙仅记 `shared_wall`，均不能据此创建人员通行红点。建筑入口继续沿用 E 编号和入口位置标记，不混入室内 P 编号。
- 同步修改 JSON、SVG、MD。MD 概括红点数、对应关系数和未定位的概念连通数。旧样本允许暂缺 `openings`，不因该字段可选就称其已恢复；恢复时须回看本图原图，不借用其他医院的点位。

## 名称是完成条件

先放大原图辨认文字，OCR 仅辅助。名称没有确定时：

1. 保留稳定的 S 编号，名称标为未确认、类型为 `unknown`；SVG 上将该区域标黄并显示“名称未确认”。候选名称不能当作确定名称。
2. 按下节制作完整原图上的编号核对总图和可编辑的名称预估表，默认直接加入现有 `标注说明.md`；每组待确认问题旁必须直接嵌入清晰的局部放大图，让用户在同一 MD 中边看图边填写。用户也可在聊天中按编号确认，只问会影响功能和连通判断的问题。
3. 收到回答后保留用户原名，将其归入共享类别，同步改 JSON、SVG 和 MD，保留已有其他确认。
4. 在所有名称确定前，称为“标注草稿／未完成”，**不能以格式可转换为 GCN 输入、几何检查通过或准备批量标注为理由宣称打标完成**。也不能用猜测或未经确认的“辅助用房”等名称绕过此条件。

用户明确接受较粗的功能名称时，按该名称记录即可。无法确定的名称继续显示在 MD 的未完成清单中；不要求用户补施工细节。

## 未确认空间的核对图与提问

默认采用**完整原图居中、待确认房间彩框、左右边栏标签、引线一一对应**的高清核对总图，保留房间之间的空间关系；同时为每组待确认问题提供局部放大图。总图用于定位，局部图用于判断。原图文件不改动；框、标签和引线是叠加层，不用独立截图或缩略图拼贴替代总图。

- **按空间顺序组织：**先将相邻房间组成连续片区，片区按图面从上到下处理；每个片区内部先上后下，同一排从左到右。先排完一组相邻房间，再进入下一组，不在远隔片区之间来回跳。
- **编号连续且对应稳定：**新图首次分配 S 编号时就按上述空间顺序安排。已有稳定 S 编号不为排版而改写；待确认空间的核对号采用连续的 `01、02、03…`，标签同时注明原 S 编号，如 `01｜S035 名称未确认`。对应关系放在草稿 MD 预估表或外部核对材料，不增加核心 JSON 字段；同一轮分批回答时保持对应不变，不因部分项已确认而重排余下编号。
- **标签顺序与图面一致：**每组边栏标签按核对号从上到下连续排列，空间框、编号、边栏标签及提问使用同一顺序。不要为了容纳标签，把同一组排成 `18、35、21、16` 这样的跳号顺序。
- **引线不交叉：**相邻房间的标签集中放在靠近该片区的同一侧，必要时分放左右两栏或调整留白、折线走向。发现交叉先调整标签位置和连线，不用打乱编号解决；避免长线横穿无关片区。分组颜色保持框、引线和标签一致。
- **集中展示，按编号确认：**提交时说明待确认数量、读取方向和回复格式，例如 `01=诊室，02=治疗室`；用户也可直接用原 S 编号回答。允许一次确认全部或分批回复，不强迫逐张打开、每次只答少量截图。未回答的项继续保留为未确认，已确认的名称不丢失。
- **核对图也要检查：**查看全图和密集局部，确认全部待确认空间都有且只有一个核对号、无漏项或错指、相邻房间顺序连贯、边栏标签无跳号、引线无交叉、放大后可读。核对图及局部图放在样本目录之外的可持续保存的核对目录，最终样本仍只保留四文件。

用户要求先确认理解时，先用文字复述图式、排序与连线规则，得到确认后再改图；用户已经确认的样式可沿用，不必每张图重复询问。

## 在 MD 中看局部图并直接填写

房间名称、空间属性和门洞／连通关系的待确认问题均适用。每组按“固定核对号与片区标题 → 局部图 → 需确认内容 → 可填写表”连续编排，图片和对应填写位置放在一起，不让用户在文档两端来回查找。

- **先筛选再交付：**连通复核先执行上节的三类筛选；仅把仍需用户判断的关键疑点编入填写区。局部图应聚焦本题，保留必要邻接上下文，不用整幅大图代替局部判断。
- **连通问题用短问答：**默认按“局部图 → 一句明确问题 → 我的判断（简短依据）→ 我的确认／备注”呈现；用户可以只填“同意”或直接改写，不必重述整套连接。名称预估表用于未定房名，不把它的宽表和多候选结构套入每个连通问题。多个独立判断各留一个填写处；自动预填和未作答都不视为用户确认。

```markdown
### 04｜北侧交通核 S040
![04：交通核及相邻通道](相对路径/04_局部.png)
**问题：**S040 是否直接连向北侧通道 Sxxx？
**我的判断：**倾向相通；通道在该侧衔接，开口仍不清楚。
**我的确认／备注：**待填写（同意，或写实际相连空间；无需确定具体门位）
```

- **直接显示图片：**使用 Markdown 图片语法 `![核对号与片区说明](相对路径)` 嵌入，不以普通图片链接代替；可另附打开原尺寸图的链接。总图保留为定位概览。
- **保留判断上下文：**局部图包括目标房间、必要的相邻空间和走廊；连通问题保留门洞／疑似开口及两端空间。显示固定核对号和相关 S 编号；标记不能遮挡原字、门扇或开口。必要时另附同范围的无标记原图。
- **按阅读尺寸检查：**在实际 MD 预览中确认编号和关键细节可辨。密集片区继续拆分局部图；同组远隔位置用 `09-A`、`09-B` 等图号补充，原核对号与 S 编号映射不变。放大不能恢复原图缺失的信息，仍不清楚的地方如实列为待确认。
- **沿用一份填写材料：**名称预估表沿用下节字段和已有填写；连通问题在对应图旁保留“我的确认／备注”等现有确认栏，说明可填“同意”、实际直接相通的空间名称／S 编号或“待确认”。关系判断优先于入口侧，只有确实影响主要连接时才追问朝向。搬动表格或改成短问答时保留原答案与备注，不另设需重复填写的答案表。
- **持久保存并核验：**局部图放在正式四文件目录之外的工作区核对目录，MD 通过有效相对路径引用。检查每个待确认问题都有对应局部图、图号与表号一致、相关空间无漏裁、全部嵌入图片可加载、用户填写未丢失。

## MD 中可直接修改的名称预估表

有未确认空间时，默认在现有 `标注说明.md` 的概览后加入预估表，按相同片区分组、相同固定核对号排列，一项一行，让用户在同一 MD 中看图和改名。用户指定已有文件时沿用该文件；已有独立 `待确认清单.md` 或用户要求独立清单时继续使用，不另外维护一份需要重复填写的表。

核对总图、局部图及映射默认放在工作区内、最终样本目录外的 `临时核对/<项目编号与名称>/` 等可持续保存的目录，避免只放在系统 `/tmp` 或 `/private/tmp`。MD 用相对路径嵌入总图，并在各片区表格附近直接嵌入同号局部图，提供原图和具名 SVG 链接；图片可放大且路径实际存在。沿用用户指定的目录，不迁移或覆盖用户正在填写的材料。

表格至少包含：

| 核对号 | S编号 | 预估名称（可改） | 备选名称 | 依据与把握 | 我的确认／备注 | 核对号（重复） |
| --- | --- | --- | --- | --- | --- | --- |
| 01 | S035 | 抢救室 | 留观室 | 示例：可见诊疗床，两候选共用该依据；仅凭床位不能区分。把握：低。 | 待确认 | 01 |

- **两端显示核对号：**表格最右侧增加“核对号（重复）”，逐行原样重复左侧核对号，保留前导零，方便对照较宽的表格；这是同一编号的显示，不另行编号。读取填写内容时按确认栏的列名定位，不把最右侧编号当作用户答案；左右号不一致时先检查对应关系。
- **直接修改：**说明用户可修改“预估名称（可改）”，核对后将“我的确认／备注”栏改为“已确认”；接受原预估时只改该栏即可，也可在该栏填写实际名称或备注。默认全部为“待确认”。保留已有表格的列名与填写习惯：旧表的“最终确认”可填本行 A/B 等选项字母或实际名称，初始留空，不强制换表。
- **逐项说明理由：**每个空间的每个候选都要说明依据，区分图中文字／OCR线索、设备家具、位置与相邻关系、片区背景推测，并写明无法确定之处。多个选项只有共同依据时，明确写出哪些选项共用该依据、现有证据不能区分；不能把候选名称反过来当证据，也不能编造设施或门洞。
- **弱证据如实写：**仅知所属片区时，写“仅依片区功能推测，缺乏房间级证据”，把握标低；没有可用依据时写“暂无可靠候选／依据不足”，由用户自由填写，不强行补 A/B。把握用高／中／低，取决于证据强弱，不以文字篇幅或常见配置充当把握。
- **保护已有填写：**补充理由、调整排版或续作前先读取现有文件，保留用户改过的预估名称、确认状态、备注及选项字母对应，不覆盖为新空表。已确认的行在同轮续作中保留，核对号与 S编号的对应不变，新增候选不能改变已有字母含义。
- **读取并同步：**用户要求更新时读取实际文件。“已确认”接受本行当前修改后的预估名称；明确填写的实际名称、旧表有效选项字母及聊天中的确认也可采用，保留用户原名。用户明确说明整表已是最终名称时按其说明处理，无须再强制逐行标记。只同步明确确认项到 JSON、SVG、MD；仅有自动预填、保存文件或含糊备注不等于确认整表，空白、“待确认”“待定”和越界字母继续未确认并集中说明。
- **内院另核面积：**露天内院、挑空／上空等项在确认栏提示补充“露天／挑空，不计室内面积”或“室内可步入，计室内面积”。功能名称确认与面积属性分别判断，不凭内院名称或候选把握自动排除面积。仅名称确认、露天／室内属性仍不明时，可保存用户确认的名称，但该项暂保留 `unknown` 及既有草稿面积口径，在 MD 单列属性待确认；待属性明确后再分类、归一化，不宣布完成。
- **生成概览时保留表格：**运行 `summary` 会重写输出 MD；执行前保存用户填写，生成概览后恢复尚在使用的预估表、已确认内容及有效图片链接，避免丢失分批修改。全部确认且正式校验通过后，将最终 MD 收敛为简短概览；填写过程如需留存放在外部核对目录，保留用户材料，不擅自删除。
- **检查表格：**当前 JSON 中每个待确认项都有且只有一行，另允许保留本轮已确认行及其确认标识；核对号连续且映射稳定，理由／证据不足说明及把握齐全，图片链接有效，已有填写未丢失。候选、理由、问答及确认状态只存在草稿 MD 或外部核对材料；确认前核心 JSON 保持 `unknown`，SVG仍显示名称未确认。

## 核心数据

读 [schema.md](references/schema.md) 按约定保存 `image`、`spaces`、`relations`。沿用 [space-types.json](references/space-types.json) 的统一功能类别；用户确认的新功能若无法归类，再补充有意义的共用类别，而不是为每个房间单独创造类型。

室内非重叠区域的 `area_ratio` 合计为 1；绿化及已确认不计室内面积的露天／挑空中庭保留编号和轮廓，不参与归一化。后者采用 `type: courtyard`、`level: open_space`；室内可步入的中庭不能仅凭名称排除面积。不保存平方米面积或像素面积字段。入口是关系中的一种，保存入口名称、类型、近似位置和所连空间；不重复维护入口表，也不通过一个“室外总节点”把所有入口互连。

最终 JSON 不保存人工问答、审核日志或推断过程。确认后的事实体现在名称和连接中。未记关系不自动当负样本；原图坐标是标注信息，不能在预测新方案时不加区分地作为已知输入。GCN 训练和 Rhino 执行不在本 Skill 的任务范围内。

## 辅助工具与核验

以下命令中将 `<skill>` 替换为本文件所在目录，`<json>` 为当前样本：

```bash
uv run --with pymupdf --with shapely python <skill>/scripts/annotation_tools.py normalize <json>
uv run --with pymupdf --with shapely python <skill>/scripts/annotation_tools.py render <json> --output <svg>
uv run --with pymupdf --with shapely python <skill>/scripts/annotation_tools.py summary <json> --output <md>
uv run --with pymupdf --with shapely python <skill>/scripts/annotation_tools.py validate <json> --check-dir
```

脚本不负责自动识别房间；由助手直接看图和核验语义。现有 `questions <json> --out-dir <临时目录>` 只生成单空间局部截图，枚举顺序不保证符合图面顺序，也不生成上述边栏引线总图；它可作辅助素材，不能直接替代核对总图的编排与目视核验。草稿可用 `validate --allow-incomplete` 检查结构；**它不代表已完成**。正式 `validate` 返回 2 表示仍有名称未确认，返回 1 表示结构或几何等错误。

MD 概括范围、空间／类型数量、各类关系数量、入口和必要精度说明；不写成程序操作说明。SVG 要实际画出名称，不能只把名称放在悬停标题或外部 JSON 中。

交付前运行正式检查，并渲染 SVG 查看完整图及密集小房间局部，核对可见名称、边界、入口、门洞红点与 JSON 的空间对及坐标一致。`validate --check-dir` 检查红点和 `openings` 的编号、坐标及两端空间对应；它不能替代原图目视判读门洞。检查通过且目标层级的关键疑点已解决后才宣布这张图按概念精度完成；仍待用户判断的关键关系须如实列出。格式检查通过不代表已验证模型泛化或整批样本量充分。

经用户确认的案例事实留在该图数据；有复用价值的判读经验再归纳进规则或共享类别，不把单院特例当成所有图纸的固定规则。
