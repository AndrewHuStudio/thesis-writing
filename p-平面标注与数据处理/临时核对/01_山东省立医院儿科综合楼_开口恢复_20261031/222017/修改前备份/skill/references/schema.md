# 四文件与核心 JSON 约定

最终每图目录为：原图、SVG、JSON、MD。现有文件名优先；原图不改动。

JSON 顶层只有 `image`、`spaces`、`relations`。

## image

`file`：同目录原图文件名；`width`、`height`：标注使用的图像像素尺寸。左上原点，x 向右、y 向下。PDF 需先确定单页及工作像素坐标，最终仍保留原始单页 PDF；临时栅格化不新增最终文件。

## spaces

| 字段 | 含义 |
| --- | --- |
| id | 稳定空间编号，同一图内唯一，如 S001 |
| name | 原图可读或用户明确给出的名称；不随意改写用户用词 |
| type | 共用功能类别代码，见 space-types.json |
| level | room、open_space、semi_open_space、core_block、functional_block、landscape |
| scope | 功能范围，如 ordinary_outpatient、emergency、public_service；同项目一致 |
| polygon_px | 原图像素多边形，至少三个顶点；不同标注单元不重复占地 |
| area_ratio | 室内占比；各非重叠室内区域面积之和为分母。绿化不保存此字段 |

不保留 `area_m2`、`area_px2`、人工确认记录和施工细节字段。面积可从多边形计算。原图中穿越区域的轴线、家具和铺地图案不自动构成房间隔墙。

已确认不计入室内面积的露天／挑空中庭采用 `type: courtyard`、`level: open_space`，保留编号及轮廓，不保存 `area_ratio`。室内可步入的中庭仍按实际室内功能归类，不能仅凭“中庭”名称排除面积。绿化和 `courtyard` 均不参与室内归一化。

未确认名称可在草稿中保留 `unknown`，但这会阻止正式完成校验；不得把候选功能当作已确定标签。

## relations

普通关系字段：`id`、`source`、`target`、`type`。

- `access`：空间之间的概念级人员可达。门、无门开口、经确认的区域连续均可形成该关系。不同门连接同一空间对时合并。
- `service`：服务窗口／柜台联系，不由此推断人员可穿行。
- `shared_wall`：共墙，不自动表示可达。
- `entrance`：额外保存 `name`、`entrance_type`、`position_px`；`source: null` 表示外部边界接口，`target` 为直接相连室内空间，独立 E 编号。

空间关系按无向概念联系存储，每对空间同一类型只保留一条；不同类型可并存。入口箭头不自动解释为单向权限。外部端点 null 不是供室内寻路的共享室外节点。训练时入口是否转换为特殊节点，由预处理决定。

不保存门坐标、门宽、门扇、半墙缺口和内部精确路径。关系存在不表达患者／医护门禁权限，除非另行定义了相应研究任务。

## MD 与 SVG

最终 MD 是短概览：范围、总数、各类数量、关系分类计数、入口及必要精度说明。草稿有未确认名称时，默认在同一 MD 中加入 SKILL.md 规定的可编辑名称预估表、核对图及局部图链接，并明确未完成；用户填表期间保留其名称修改、确认状态与备注，生成概览时不得覆盖这些内容。全部确认并正式校验通过后再收敛为最终概览。

SVG 自带原图底图；每个空间都可见“编号＋名称”。名称未确定的区域用显著颜色显示“名称未确认”；用户确认采用 SKILL.md 规定的完整原图框选、边栏标签和引线总图，局部放大图为补充。名称不能仅存在于 SVG 的 title 元素。

核对总图按连续片区自上而下、同排自左向右编排，标签按同一顺序排列，引线不交叉。已有 S 编号保持稳定；需要无跳号核对时，使用连续核对号并在标签注明对应 S 编号。对应关系保存在草稿 MD 预估表或外部核对材料中，不加入 `image`、`spaces` 或 `relations`，不影响最终四文件约定。图片与核对材料按 SKILL.md 放在工作区内、最终样本目录外的可持续保存目录，MD使用可解析的相对图片路径。

## 完成检查

完成需要：名称确定、类别统一、编号／关系有效、多边形有效且不重叠、面积归一化、SVG 可见名称与 JSON 一致、四文件交付。按用户原名记载不等于有现场测绘证据；不要作超出当前图纸与用户说明的建筑合规或模型效果承诺。
